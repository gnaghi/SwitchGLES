# SwitchGLES Architecture and Design Document\n\n## 1. System Overview\n\n### What is SwitchGLES?\n\nSwitchGLES is a complete OpenGL ES 2.0 and EGL 1.4 implementation targeting the Nintendo Switch. It translates standard OpenGL ES API calls into commands for deko3d, the Switch's low-level, Vulkan-like GPU command buffer API built on NVIDIA's Maxwell architecture (Tegra X1).\n\nThe project exists because the Switch has no official OpenGL driver. deko3d provides direct hardware access but speaks an entirely different language than OpenGL. SwitchGLES bridges that gap, enabling applications written against the GLES 2.0 spec -- including Quake 3 (spearmint engine) and the Khronos dEQP-GLES2 conformance test suite -- to run on Switch hardware.\n\n### Relationship to External Components\n\n- **deko3d** -- NVIDIA Tegra X1 command buffer API provided by devkitPro. SwitchGLES creates a `DkDevice`, allocates `DkMemBlock` pools, records into `DkCmdBuf`, and submits via `DkQueue`. deko3d is consumed as a pre-built static library; SwitchGLES has no ability to modify it.\n\n- **uam (Mesa + NV50_IR)** -- Shader compiler. Wraps Mesa's GLSL compiler frontend and NV50_IR (NVIDIA's intermediate representation) backend to produce DKSH binaries (deko3d shader format). SwitchGLES links uam as a static library (`libuam.a`) when the `SGL_ENABLE_RUNTIME_COMPILER` flag is defined. uam provides a C API (`uam_compile_dksh`, `uam_get_uniform_info`, etc.) for both compilation and metadata extraction.\n\n- **Mesa** -- Used indirectly through uam. Mesa's `gl_nir_link_uniforms()` handles driver constant buffer remapping, and Mesa's GLSL compiler handles ES 1.00 source directly (bypassing the transpiler for 99.7% of shaders).\n\n### API Coverage\n\n- **GLES 2.0**: Fully implemented. 226 validation tests pass. dEQP-GLES2 has 15,956 of 17,165 tests passing (92.9%).\n- **EGL 1.4**: Fully implemented. Display, surface, context, and swapchain lifecycle are complete.\n- **GLES 3.0**: Headers are included. Partial support exists (`glBlitFramebuffer`, `glRenderbufferStorageMultisample` stub, GLES 3.0 format constants).\n\n---\n\n## 2. Architecture Layers\n\n### 4-Layer Design\n\n```\n+--------------------------------------------------------------------+\n|  Layer 1: GL Entry Points (gl_draw.c, gl_texture.c, gl_shader.c,  |\n|           gl_uniform.c, gl_framebuffer.c, gl_state.c, gl_buffer.c, |\n|           gl_query.c)                                               |\n|  - Implements every glXxx() function                                |\n|  - Parameter validation, error generation                           |\n|  - MUST NOT include <deko3d.h>                                      |\n+--------------------------------------------------------------------+\n       |  ctx->backend->ops->xxx()\n       v\n+--------------------------------------------------------------------+\n|  Layer 2: Context / State / Resources                               |\n|  - sgl_context_t: blend, depth, raster, viewport, color state      |\n|  - sgl_resource_manager_t: pools for buffers, shaders, programs,    |\n|    textures, framebuffers, renderbuffers                            |\n|  - sgl_gl_types.h: all type definitions                            |\n+--------------------------------------------------------------------+\n       |  function pointer dispatch\n       v\n+--------------------------------------------------------------------+\n|  Layer 3: Backend Interface (sgl_backend.h)                        |\n|  - sgl_backend_ops_t: 50+ function pointers                        |\n|  - sgl_backend_t: ops table + void *impl_data                      |\n|  - Backend-agnostic state types (sgl_backend_types.h)              |\n+--------------------------------------------------------------------+\n       |  dk_xxx() implementations\n       v\n+--------------------------------------------------------------------+\n|  Layer 4: deko3d Backend (dk_backend.c, dk_command.c, dk_state.c,  |\n|           dk_clear.c, dk_buffer.c, dk_draw.c, dk_uniform.c,        |\n|           dk_shader.c, dk_texture.c, dk_framebuffer.c, dk_utils.c) |\n|  - Direct deko3d API calls: DkCmdBuf, DkMemBlock, DkQueue, etc.    |\n|  - dk_backend_data_t: GPU memory pools, per-texture/shader arrays  |\n+--------------------------------------------------------------------+\n```\n\nThe strict layering ensures that the GL layer never calls deko3d directly. Every GPU operation goes through `ctx->backend->ops->function_name()`. This was an explicit design choice documented in `gl_common.h` with the comment: \"This layer must NOT include any deko3d headers!\"\n\n### Data Flow: A Typical Draw Call (`glDrawArrays`)\n\n1. **GL entry point** (`gl_draw.c:glDrawArrays`):\n   - Calls `sgl_ensure_frame_ready()` -- deferred frame acquisition if needed.\n   - Validates mode, count, framebuffer completeness, program state.\n   - Calls `sgl_prepare_draw(ctx)`.\n\n2. **State application** (`sgl_prepare_draw`):\n   - Pushes ALL GL state to the backend every draw (no dirty flags):\n     - Viewport, combined depth-stencil, blend, rasterizer, color mask, scissor.\n   - Populates `gl_DepthRange` built-in values into packed UBO shadow buffers.\n   - Calls `sgl_bind_program_for_draw()` to bind shaders + uniforms.\n   - Binds textures per-sampler (sampler-driven binding using program's sampler table).\n\n3. **Vertex attribute preparation** (`glDrawArrays` continued):\n   - Copies `ctx->vertex_attribs[]` to local `prepared_attribs[]`.\n   - For each enabled attribute backed by a VBO, computes `buffer_offset = buf->data_offset + pointer_offset`.\n   - Calls `backend->ops->bind_vertex_attribs()`.\n\n4. **Backend vertex binding** (`dk_draw.c:dk_bind_vertex_attribs`):\n   - For VBO-backed attributes: sets `DkVtxAttribState` with GPU offset.\n   - For client-array attributes: copies vertex data to the per-slot client array region, issues `dsb st` ARM write barrier, sets GPU address.\n   - For GL_FIXED type: CPU-converts 16.16 fixed-point to float via staging.\n   - Emits `dkCmdBufBindVtxAttribState` + `dkCmdBufBindVtxBufferState`.\n\n5. **Backend draw** (`dk_draw.c:dk_draw_arrays`):\n   - Calls `dkCmdBufDraw(dk->cmdbuf, mode, first, count, 1)`.\n   - Increments `diag_draw_count` and `draws_since_flush`.\n\n### Data Flow: Shader Compilation\n\n```\nglShaderSource(shader, source)\n     |\n     v\nglCompileShader(shader)\n     |\n     +-- Is GLSL ES 1.00? (sgl_is_es100_source)\n     |   |\n     |   +-- YES: Run ES 1.00 validation (glslt_validate_es100)\n     |   |        |\n     |   |        +-- Try Mesa direct (sgl_compile_es100_mesa)\n     |   |        |   - uam_compile_dksh() with raw ES 1.00 source\n     |   |        |   - Capture uniform/sampler/input metadata\n     |   |        |   - On success: shader.compiled_via_mesa = true\n     |   |        |\n     |   |        +-- Mesa failed with errors? -> compilation fails\n     |   |        |\n     |   |        +-- Mesa failed silently? -> Transpiler fallback\n     |   |             - glslt_transpile(): ES 1.00 -> GLSL 4.60\n     |   |             - shader.needs_transpile = true (deferred to link)\n     |   |\n     |   +-- NO: Compile as GLSL 4.60 directly\n     |           - sgl_compile_glsl460() -> uam_compile_dksh()\n     |           - Shader cache lookup/store\n     |\n     v\nglLinkProgram(program)\n     |\n     +-- Mesa path (both shaders compiled_via_mesa):\n     |   - Extract metadata from sgl_mesa_metadata_t\n     |   - Build program_uniforms[] from constbuf offsets\n     |   - Build samplers[] from sampler metadata\n     |   - Build attrib_bindings[] from input metadata\n     |\n     +-- Transpiler path (any shader.needs_transpile):\n     |   - Run glslt_transpile() on both shaders\n     |   - Extract uniform/sampler reflection from transpiler\n     |   - Compile transpiled GLSL 4.60 -> DKSH via uam\n     |   - Register packed UBO sizes from transpiler\n     |\n     +-- Backend link: dk_link_program()\n         - Copy DkShader structs to program_shaders[prog][0/1]\n         - Track active_shader_count, active_program_count\n```\n\n---\n\n## 3. Memory Layout\n\n### GPU Memory Regions\n\nSwitchGLES allocates five `DkMemBlock` pools at backend initialization:\n\n| Region | Size | Flags | Purpose |\n|--------|------|-------|---------|\n| `code_memblock` | 16 MB | CpuUncached + GpuCached + Code | DKSH shader binaries |\n| `data_memblock` | 256 MB | CpuUncached + GpuCached | VBOs + client arrays + uniforms |\n| `texture_memblock` | 128 MB | GpuCached + Image | Texture pixel data |\n| `descriptor_memblock` | 64 KB | CpuUncached + GpuCached | Image + sampler descriptors |\n| `cmdbuf_memblock[3]` | 4 MB each | CpuUncached + GpuCached | Per-slot command buffers |\n\n### Data Memory Sub-Regions\n\nThe 256 MB `data_memblock` is partitioned at init time:\n\n```\nOffset 0                        192 MB                      255 MB   256 MB\n|--- Static VBO/EBO region ---|--- Client array region ---|-- Uniforms --|\n     (bump allocator +              (per-slot, triple-        (1 MB,\n      VBO free list)                 buffered)                 reset/frame)\n\nDetails:\n  [256 .. 192 MB)     Static VBOs: bump allocator with first-fit free list\n  [192 MB .. 255 MB)  Client arrays: 63 MB total, ~21 MB per slot\n  [255 MB .. 256 MB)  Uniform staging: 1 MB, reset to 0 each frame\n```\n\nOffset 0 is reserved as an error sentinel (allocations returning 0 indicate failure).\n\n### Triple Buffering and Per-Slot Resources\n\n`SGL_FB_NUM = 3` governs triple buffering:\n\n- **3 command buffers** (`DkCmdBuf cmdbufs[3]`): Each framebuffer slot has its own command buffer and memory block, preventing GPU command conflicts.\n- **3 fences** (`DkFence fences[3]`): Per-slot synchronization. `dk_wait_fence()` blocks until a slot's previous work completes before reusing its command buffer.\n- **3 depth buffers** (`DkImage depthbuffers[3]`): Created in `eglCreateWindowSurface`, one per slot.\n- **Per-slot client array regions**: The 63 MB client array space is divided by 3. Each slot's sub-region is bounded by `client_array_offset` and `client_array_slot_end`. This prevents CPU writes for slot N from corrupting data still being rendered from slot N-1.\n\n### Client Array Staging\n\nWhen a vertex attribute uses a client pointer (no VBO bound), the draw path copies vertex data into the current slot's client array region:\n\n1. Compute byte size needed: `count * stride`.\n2. Allocate from `client_array_offset` (bump allocator within slot bounds).\n3. `memcpy()` data from application pointer to `data_memblock` CPU address.\n4. Issue `__asm__ volatile(\"dsb st\" ::: \"memory\")` -- ARM write barrier to ensure the GPU sees the data.\n5. Set `DkVtxBufferState` GPU address to `dkMemBlockGetGpuAddr(data_memblock) + client_array_base + client_array_offset`.\n\n### Uniform Staging (pushConstants)\n\ndeko3d uses `dkCmdBufPushConstants()` to embed uniform data directly into the command buffer at record time. This is critical because it captures uniform values at the point they are recorded, not at GPU execution time, preventing race conditions when multiple draws have different uniform values.\n\nThe flow per draw:\n1. **Packed UBO shadow buffers** (`sgl_packed_ubo_t.data[]`, CPU-side 8 KB max): `glUniform*()` writes into these shadows. Each packed UBO has a `dirty` flag.\n2. At draw time in `dk_bind_program()`:\n   - Allocate 256-byte-aligned space from `uniform_offset`.\n   - `memcpy()` shadow buffer to `data_memblock + uniform_base + offset`.\n   - `dkCmdBufBindUniformBuffer()` + `dkCmdBufPushConstants()`.\n3. `uniform_offset` is reset to 0 in `dk_wait_fence()` at frame start.\n\n---\n\n## 4. Shader Compilation Pipeline\n\n### Two Paths: Mesa Direct vs. Transpiler Fallback\n\n**Path 1: Mesa Direct (preferred, handles 99.7% of shaders)**\n\nWhen `glCompileShader()` receives ES 1.00 source (detected by `sgl_is_es100_source()`), it first runs `glslt_validate_es100()` for spec-compliance checks that Mesa does not enforce (Mesa compiles as GLSL 4.60 core internally), then calls `sgl_compile_es100_mesa()`:\n\n- Creates a `uam_compiler` for the appropriate stage.\n- Calls `uam_compile_dksh()` with the raw ES 1.00 source.\n- On success, extracts metadata via `uam_get_num_uniforms()`, `uam_get_uniform_info()`, `uam_get_num_samplers()`, `uam_get_sampler_info()`, `uam_get_num_inputs()`, `uam_get_input_info()`.\n- Stores metadata in `sgl_mesa_metadata_t` on the shader object.\n- Sets `compiled_via_mesa = true`.\n\n**Path 2: Transpiler Fallback (0.3% of shaders)**\n\nIf Mesa fails silently (no error log -- meaning the source uses constructs Mesa cannot handle rather than being invalid), the transpiler kicks in:\n\n- `glslt_transpile()` converts ES 1.00 to GLSL 4.60 core:\n  - `attribute` -> `in`, `varying` -> `out/in`\n  - `texture2D()` -> `texture()`, `textureCube()` -> `texture()`\n  - `gl_FragColor` -> `_sgl_FragColor` (explicit output)\n  - `precision mediump float;` -> stripped\n  - Uniforms -> `layout(std140, binding=N) uniform Block { ... }` UBO syntax\n  - Struct members flattened: `uniform MyStruct s;` with field `a` becomes `s_a` in the UBO\n  - Sampler arrays expanded: `uniform sampler2D s[4];` becomes `s_0`, `s_1`, `s_2`, `s_3`\n  - `gl_MaxXxx` constants replaced with literal values matching `glGetIntegerv()`\n- Sets `needs_transpile = true` (actual compilation deferred to `glLinkProgram()`).\n\nIf Mesa fails with errors (info_log set), the shader is rejected. The transpiler is NOT tried, because it lacks semantic analysis and would incorrectly accept invalid shaders. This design choice fixes 72 dEQP failures.\n\n### ES 1.00 Detection (`sgl_is_es100_source`)\n\nReturns true if:\n- Source starts with `#version 100`, OR\n- No `#version` directive but contains ES-specific keywords: `attribute`, `varying`, `gl_FragColor`, `gl_FragData`, `precision`, `mediump`, `highp`, `lowp`.\n\nReturns false for garbage text with no `#version` (allows uam/Mesa to report the error).\n\n### Uniform Metadata Extraction (Packed UBO System)\n\nThe packed UBO system encodes uniform locations as bit-packed `GLint` values:\n\n```\nBit layout of a packed uniform location:\n[30]     SGL_LOC_PACKED_FLAG (1 = packed UBO, 0 = legacy)\n[29]     SGL_LOC_SAMPLER_FLAG (1 = sampler)\n[28:24]  Stage (0 = vertex, 1 = fragment)\n[23:16]  Binding (UBO binding index, 0-255)\n[15:0]   Byte offset within UBO (0-65535)\n```\n\nCritical design constraint: bit 31 must always be 0, because `GLint` is signed and GLES applications check `glGetUniformLocation() < 0` to detect inactive uniforms. Using bit 31 as a flag made all packed locations negative, causing dEQP to silently skip ALL uniform data. This was the root cause of hundreds of test failures (fixed by moving the flag to bit 30).\n\n**Mesa path metadata flow** (at link time):\n- For each uniform in `shader->mesa_meta->uniforms[]`:\n  - Name, byte offset in constbuf, size, GL type, array count.\n  - Stored as `sgl_program_uniform_loc_t` in `program->program_uniforms[]`.\n  - Location = `SGL_LOC_PACKED_FLAG | (stage << 24) | (0 << 16) | offset`.\n- Constbuf initial data (literal constants embedded by Mesa) is copied to the packed UBO shadow at link time.\n\n**Transpiler path metadata flow** (at link time):\n- Transpiler's `glslt_result_t` contains `uniforms[]` with name, type, std140 offset.\n- Registered via `sglRegisterPackedUniform()` into the program's uniform table.\n- Packed UBO sizes set via `sglSetPackedUBOSize()`.\n\n### Sampler Binding System\n\nSamplers require special handling because deko3d binds textures to descriptor slots by index, while GLES uses `glUniform1i()` to assign texture units to sampler uniforms.\n\nEach program maintains a `samplers[]` array (`sgl_program_sampler_t`):\n- `shader_binding`: The `layout(binding=N)` slot in the compiled shader (FS stage).\n- `vs_shader_binding`: Separate binding for VS when sampler exists in both stages (-1 if FS-only).\n- `tex_unit`: The GL texture unit assigned via `glUniform1i()`. Defaults to 0 (per GLES2 spec: all samplers initially map to texture unit 0).\n- `gl_type`: `GL_SAMPLER_2D` or `GL_SAMPLER_CUBE`.\n\nAt draw time, `sgl_prepare_draw()` iterates program samplers and binds textures:\n```\nfor each sampler in program:\n    tex_id = ctx->bound_textures[sampler.tex_unit]   // or bound_cubemap_textures\n    if tex_id == 0 or texture incomplete:\n        bind black fallback (1x1 RGBA 0,0,0,255 per GLES2 section 3.7.10)\n    else:\n        backend->ops->bind_texture(unit=sampler.shader_binding, tex_id, stage)\n```\n\n---\n\n## 5. Texture System\n\n### Format Conversion (GL -> DkImageFormat)\n\n`dk_convert_format()` in `dk_utils.c` maps GL format/type pairs to deko3d formats. Key mappings:\n\n| GL Format | GL Type | DkImageFormat |\n|-----------|---------|---------------|\n| GL_RGBA | GL_UNSIGNED_BYTE | RGBA8_Unorm |\n| GL_RGB | GL_UNSIGNED_BYTE | RGBA8_Unorm (expanded from RGB) |\n| GL_LUMINANCE | GL_UNSIGNED_BYTE | R8_Unorm (swizzle: RRRR -> RGBA) |\n| GL_ALPHA | GL_UNSIGNED_BYTE | R8_Unorm (swizzle: 000R) |\n| GL_LUMINANCE_ALPHA | GL_UNSIGNED_BYTE | RG8_Unorm (swizzle: RRRA) |\n| ETC1_RGB8_OES | - | DkImageFormat_ETC1 |\n\nLUMINANCE, ALPHA, and LUMINANCE_ALPHA formats do not have native deko3d equivalents. SwitchGLES uses `DkImageView.swizzle[4]` for zero-cost channel remapping, combined with bpp-aware staging (1 or 2 bytes per pixel instead of 4).\n\n### Staging Upload (CPU -> GPU)\n\nTexture upload (`dk_texture_image_2d`) follows this sequence:\n\n1. Convert GL format/type to `DkImageFormat`.\n2. Allocate GPU memory from `texture_memblock` (bump allocator with free list).\n3. For RGB input data: expand 3 bytes/pixel to 4 bytes/pixel (RGBA) in a temporary buffer.\n4. Create a temporary `DkMemBlock` with `CpuUncached | GpuCached` for the staging buffer.\n5. `memcpy()` pixel data into staging block.\n6. Set up `DkCopyBuf` (source) and `DkImageRect` (destination).\n7. `dkCmdBufCopyBufferToImage()` to blit from staging to texture memory.\n8. `dkQueueSubmitCommands()` + `dkQueueWaitIdle()` -- synchronous upload.\n9. Destroy staging memblock.\n10. Create `DkImageDescriptor` and `DkSamplerDescriptor` AFTER upload completes.\n11. Issue `dsb st` ARM write barrier to ensure descriptors are visible to GPU.\n\n### Descriptor Management (TIC/TSC)\n\nDescriptor memory is divided in half:\n- First half: `SGL_MAX_TEXTURES` image descriptors (DkImageDescriptor, 32 bytes each).\n- Second half: `SGL_MAX_TEXTURES` sampler descriptors (DkSamplerDescriptor, 32 bytes each).\n\nDescriptors are indexed by texture ID. At bind time (`dk_bind_texture`), the command buffer is told to use descriptor slot N for texture unit N via `dkCmdBufBindTextures()`.\n\nCritical initialization: ALL descriptor memory is zeroed with `memset()` at startup. Non-zero sampler descriptors combined with `DkInvalidateFlags_Descriptors` at frame start cause a startup crash.\n\nDescriptor coherency requires TWO mechanisms:\n1. `dsb st` -- ARM write barrier after CPU writes to descriptor memory.\n2. `DkInvalidateFlags_Descriptors` -- GPU TIC/TSC cache invalidation in frame-start barriers.\n\nBoth are required together. Either alone is insufficient.\n\n### Cubemap Handling\n\n- 6 faces tracked via `cubemap_face_mask[tex_id]` bitmask.\n- Faces can be uploaded in any order, at any mip level.\n- `cubemap_needs_barrier[tex_id]` set true when all 6 faces uploaded; cleared after L2 cache barrier.\n- Cubemap and 2D textures tracked independently per texture unit (`bound_textures[]` vs `bound_cubemap_textures[]`).\n\n### Texture Completeness\n\nPer GLES2 section 3.7.10, a texture is incomplete if:\n- NPOT dimensions with `REPEAT`/`MIRRORED_REPEAT` wrap mode.\n- NPOT dimensions with mipmap min filter.\n- Cubemap face dimension mismatch.\n\nIncomplete textures sample as a 1x1 black fallback texture (RGBA 0,0,0,255) created at backend init (slot 0 for 2D, slot 1 for cubemap).\n\n---\n\n## 6. Framebuffer System\n\n### FBO Attachment Model\n\nEach `sgl_framebuffer_t` tracks:\n- `color_attachment`: Texture or renderbuffer ID.\n- `depth_attachment`: Texture or renderbuffer ID or 0.\n- `stencil_attachment`: Renderbuffer ID or 0.\n- `color_is_renderbuffer`, `depth_is_renderbuffer`, `stencil_is_renderbuffer`: Type flags.\n- `color_textarget`, `depth_textarget`, `stencil_textarget`: For cubemap face queries.\n\nAttachments can be textures (via `glFramebufferTexture2D`) or renderbuffers (via `glFramebufferRenderbuffer`). Renderbuffers have dedicated `DkMemBlock` per instance (`renderbuffer_memblocks[]`).\n\n### Render Target Switching\n\nWhen `glBindFramebuffer()` changes the draw target:\n\n1. Skip if target is unchanged (redundancy check).\n2. Call `sgl_ensure_frame_ready()` (deferred frame acquisition).\n3. Insert GPU barrier (`DkBarrier_Full` with `DkInvalidateFlags_Image | L2Cache | Zcull`).\n4. Call `backend->ops->bind_framebuffer()` with attachment handles and type flags.\n5. Backend (`dk_bind_framebuffer`) resolves handles to `DkImage` references and calls `dkCmdBufBindRenderTarget()`.\n\nWhen binding FBO 0 (default framebuffer), the backend binds `framebuffers[current_slot]` and `depth_images[current_slot]`.\n\n### Deferred Deletion and Ref Counting\n\nTextures and renderbuffers used as FBO attachments have ref-counted deferred deletion:\n\n- `glDeleteTextures()` on a texture attached to an FBO: Sets `tex->delete_pending = true`, decrements `fbo_ref_count` only for the currently bound FBO (per GLES2 section 5.4.1). The actual GPU resource deletion and slot release happen when `fbo_ref_count` drops to 0 (triggered by `glDeleteFramebuffers()`).\n- `sgl_res_mgr_get_texture_any()` returns textures even when `delete_pending` is true, for FBO deferred cleanup.\n- Programs also support deferred deletion: `glDeleteProgram()` on the current program sets `delete_pending = true`; actual free happens in `glUseProgram(0)`.\n\n### ReadPixels Pipeline\n\n`dk_read_pixels()` performs GPU->CPU readback:\n1. Create temporary staging `DkMemBlock` (CpuUncached + GpuCached).\n2. `dkCmdBufCopyImageToBuffer()` from current render target to staging.\n3. Submit + WaitIdle (synchronous).\n4. `memcpy()` from staging to application buffer.\n5. Destroy staging block.\n\n`CopyTexImage2D` and `CopyTexSubImage2D` use a similar GPU->CPU->GPU roundtrip: read pixels from current framebuffer, then upload to destination texture.\n\n### Stencil-Only FBO Handling\n\nWhen an FBO has a stencil attachment but no depth attachment, `dkCmdBufClearDepthStencil` is still called with the stencil renderbuffer bound as the depth view (deko3d uses combined depth-stencil surfaces). The guard condition checks `depth == 0 AND stencil == 0` before skipping the clear, ensuring stencil-only clears still execute.\n\n---\n\n## 7. State Management\n\n### Per-Draw State Application (`sgl_prepare_draw`)\n\nSwitchGLES re-applies ALL rendering state before every draw call. There are no dirty flags. This design choice trades CPU efficiency for correctness: deko3d command buffers record state as commands, and each frame uses a different command buffer slot, so state from a previous frame does not carry over.\n\nThe order within `sgl_prepare_draw()`:\n1. Viewport\n2. Combined depth-stencil (single function, avoids overwrite bug)\n3. Blend\n4. Rasterizer (culling + polygon offset)\n5. Color mask\n6. Scissor\n7. gl_DepthRange injection into packed UBOs\n8. Program binding (shaders + uniforms via pushConstants)\n9. Texture binding (sampler-driven, per-stage)\n\n### Combined Depth-Stencil State\n\nAn early bug caused depth state to overwrite stencil state when they were applied separately (two `dkCmdBufSetDepthStencilState()` calls would each set the full structure). The fix was `apply_depth_stencil`, a single combined function that sets both depth and stencil in one call to `dkCmdBufSetDepthStencilState()`.\n\n### Blend Workaround (Raw GPU Register 0x786)\n\nThe pre-built deko3d library has a copy-paste bug in the blend factor translation: the destination blend factor register (GPU register `0x786`) gets the wrong value for certain blend modes. SwitchGLES writes the correct value directly to the raw GPU command buffer, bypassing deko3d's blend API for the destination factor. This fixed all 196 dEQP blend tests.\n\n---\n\n## 8. EGL Implementation\n\n### Device Lifecycle (Persistent Across Terminate/Initialize)\n\nThe `DkDevice` is created in `eglInitialize()` with flags:\n```c\nDkDeviceFlags_OriginLowerLeft | DkDeviceFlags_DepthMinusOneToOne\n```\n\n- `OriginLowerLeft`: Makes deko3d handle Y-coordinate flipping natively (GL has Y=0 at bottom, GPU has Y=0 at top).\n- `DepthMinusOneToOne`: GPU handles GL depth NDC [-1,1] natively, eliminating the need for shader-side depth transforms.\n\n**Anti-fragmentation persistence**: The device is NOT destroyed in `eglTerminate()`. After approximately 20 destroy/create cycles, the GPU address space fragments so severely that `dkMemBlockCreate()` fails with OOM. By keeping the device alive across terminate/initialize cycles (as used by dEQP), this fragmentation is avoided. The device is only truly destroyed at process exit.\n\n### Shutdown Order in `eglTerminate()`\n\n1. Wait all GPU queues idle (`dkQueueWaitIdle`).\n2. Destroy swapchains and surface memblocks.\n3. Destroy backends (command buffers, memory blocks, queues).\n4. Skip device destruction (anti-fragmentation).\n5. Clear context pointers.\n\n### Swapchain Management\n\n`eglCreateWindowSurface()`:\n1. Create framebuffer layout (RGBA8_Unorm, 1280x720).\n2. Allocate one `DkMemBlock` for 3 framebuffer images.\n3. If config has depth: allocate 3 separate depth memblocks (Z24S8, one per slot).\n4. Create `DkSwapchain` with NWindow.\n\nFrame lifecycle uses deferred acquisition:\n- `eglSwapBuffers()`: ends frame, presents, sets `need_acquire = true`.\n- `sgl_ensure_frame_ready()` (called from `glClear`, `glDrawArrays`, etc.): acquires next image, waits fence, begins new command buffer, restores all GL state.\n\n### Context Creation\n\n`eglCreateContext()`:\n1. Find free slot in `g_sgl.contexts[4]`.\n2. Call `sgl_context_init()` (zeroes everything, sets defaults).\n3. Call `dk_backend_create(device)` + `backend->ops->init()`.\n4. Initialize all 5 GPU memory regions.\n5. Create 1x1 black fallback texture.\n6. Call `sgl_context_init_state()` for GL state defaults.\n\n---\n\n## 9. Key Design Decisions and Trade-Offs\n\n### Why Packed UBOs Instead of Traditional Uniform Binding\n\ndeko3d requires UBO-style uniform binding (`layout(std140, binding=N) uniform Block { ... }`), not `glUniform*()` style individual uniform setting. Two approaches were considered:\n\n1. **Per-uniform UBO slots** (traditional): Each `glUniform*()` call allocates a 256-byte-aligned slot and binds it. With deko3d's `DK_UNIFORM_BUF_ALIGNMENT = 0x100`, a single float uniform wastes 252 bytes of alignment padding. Programs with 30+ uniforms and many draw calls exhaust the 1 MB uniform region quickly.\n\n2. **Packed UBOs** (chosen): All uniforms for a given stage+binding are packed into a single CPU-side shadow buffer (`sgl_packed_ubo_t.data[8192]`). `glUniform*()` writes into the shadow at the correct byte offset. At draw time, the entire shadow is uploaded once per stage. This reduces alignment waste from O(N * 256 bytes) to O(2 * 256 bytes) per draw.\n\nThe trade-off: packed UBOs require uniform layout metadata (byte offsets) from the compiler, adding complexity to the shader compilation pipeline. The Mesa direct path provides this via `uam_get_uniform_info()`, and the transpiler generates it from std140 layout rules.\n\n### Why Mesa Direct Compilation Over Transpiler\n\nMesa direct compilation became the preferred path after discovering that:\n\n1. **Coverage**: Mesa handles 99.7% of real dEQP ES 1.00 shaders correctly (1864/1870).\n2. **Semantic analysis**: Mesa correctly rejects invalid shaders (wrong types, undeclared variables, const violations). It is only destroyed at process exit.\n\nThe trade-off: ~400 MB of GPU address space remains allocated even when the display is \"terminated\".
